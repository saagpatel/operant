# OPERANT Self-Service Public Lab And Certification Pilot

This document packages the current self-service lab path: run OPERANT against
your own agent, produce a local receipt, and share the result without pretending
that a vendor or third party has certified it.

OPERANT is an evaluation layer. It measures operating-decision calibration. It
does not enforce runtime egress policy, inspect MCP server code, or certify a
deployment.

## What A User Can Try Safely

The no-secret path is the bundled heuristic adapter. It runs locally and writes a
report, summary JSON, and badge under `results/self-serve/`.

```bash
python3 selftest.py
python3 selftest_selfserve.py
python3 score_my_agent.py \
  --adapter examples/heuristic_agent.py:respond \
  --label heuristic-baseline \
  --axes decision \
  --no-judge
```

This path uses the deterministic decision scorer only. It does not call a model,
does not use a provider API key, and does not need network access.

To score your own agent, choose exactly one adapter style:

```bash
# Python callable
python3 score_my_agent.py --adapter path/to/agent.py:respond --label my-agent --axes decision --no-judge

# CLI command via stdin
python3 score_my_agent.py --cmd 'my-agent --stdin' --cmd-stdin --label my-agent --axes decision --no-judge

# HTTP endpoint
python3 score_my_agent.py \
  --endpoint https://my-agent.example/run \
  --http-body '{"input": "{prompt}"}' \
  --answer-path output.text \
  --label my-agent \
  --axes decision \
  --no-judge
```

Use a local stub or a non-production endpoint first. Do not send secrets,
customer data, private transcripts, or held-out cases to a public demo agent.

## Receipt Format

A complete self-service receipt should include:

- OPERANT version or git commit used for the run.
- Command line used, with secrets omitted.
- Agent label and adapter type: Python, CLI, or HTTP.
- Operator contract source from the report.
- Corpus source: bundled canonical corpus or an explicit `--cases` path.
- Output paths for:
  - `<label>-ocs-report.md`
  - `<label>-ocs-summary.json`
  - `operant-ocs-badge.svg`
  - `operant-ocs-badge.md`
- Decision OCS, decision accuracy, bypass leak count, unparseable count, and
  scored case count.
- Whether orchestration was scored, skipped, or unavailable.
- A limits statement: self-reported, comparable only across identical operator
  contract and corpus, not a certification.

The sample report at `examples/sample-report/heuristic-baseline-ocs-report.md`
is the intended shape. The badge snippet at
`examples/sample-report/operant-ocs-badge.md` is pasteable, but it should stay
paired with the report and limits statement.

## Badge And Report Language

Recommended badge wording:

```text
OPERANT OCS +0.394 [positive-discrimination] - acc 60% - 0 bypass leaks
```

Recommended report footer:

```text
Generated by OPERANT self-serve OCS runner. OCS is an open benchmark; this is a
self-reported score, not a certification.
```

Avoid these phrases until a real independent process exists:

- vendor certified
- OPERANT certified
- production approved
- safe agent
- benchmark winner
- leaderboard certified

Use these instead:

- self-reported OPERANT OCS receipt
- open benchmark result
- certification pilot candidate
- independent rerun requested
- comparable under the same contract and corpus

## Certification Pilot Shape

The current pilot is a lightweight evidence workflow, not a certification
authority.

Pilot-ready evidence:

- A clean self-service report generated from a public or shareable agent
  adapter.
- A machine-readable summary JSON.
- A badge paired with report-card context.
- Public artifact contract check:

```bash
python3 operant_lab_cli.py check-public-artifacts
```

- A reproducibility note naming the operator contract and corpus.

Pilot review can say:

> This result is eligible for independent rerun under the OPERANT public-lab
> pilot. It is not vendor certification. The pilot verifies that the receipt is
> complete enough to attempt an independent rerun from the provided adapter and
> honestly labeled. Reproducibility remains UNKNOWN until that rerun succeeds.

The pilot should reject or mark incomplete any result that hides the operator
contract, changes the corpus without disclosure, drops failed dispatches, omits
the self-reported caveat, or mixes Codex App and local CLI subject-shell results
as if they were one run.

## Public Lab Artifact Checks

The public export is intentionally prompt-free. Validate it before publishing:

```bash
python3 operant_lab_cli.py check-public-artifacts
```

When exporting public artifacts:

```bash
python3 operant_lab_cli.py export-public
```

Include local lab runs only when their labels are intentionally ready for public
surface:

```bash
python3 operant_lab_cli.py export-public \
  --include-lab-runs \
  --lab-labels codex-gpt55-decision-r1
```

Public artifacts must exclude raw prompts, final answers, transcripts, queue
payloads, and held-out reports.

## Current Limits

- The Claude reference bands are orientation anchors, not a certified
  leaderboard.
- Current public native-shell Codex profiles are experimental and should remain
  separated by subject shell.
- The self-service runner can score arbitrary agents, but comparability depends
  on the same operator contract and case corpus.
- The decision axis can run free and deterministic. Orchestration scoring uses
  an LLM judge when enabled and must be labeled when skipped or unavailable.
- Single-operator case authorship and small-n headline repeats remain explicit
  limitations of the current public surface.
- A badge alone is not evidence. The badge needs the report, summary JSON, and
  limits language.

## How This Complements Controls

OPERANT tells you whether the agent chose the right operating action in a
matched benign/adversarial corpus. It does not stop the agent at runtime.

Pair it with a control layer such as Cross-Provider Egress Guard when you need a
runtime receipt that non-allow-listed egress is blocked. Pair it with MCPAudit
when you need MCP/server-surface inspection. Pair it with mcpforge when you need
to build or package an MCP server surface before auditing and running it.

The combined story is control plus calibration: one receipt for what the harness
blocks, one receipt for how the agent decides.

## Current Research Anchors

AgentDojo frames prompt-injection robustness for tool-using agents, tau-bench
frames multi-turn tool-use reliability, and OPERANT's OCS focuses on
bidirectional operating calibration: withhold when warranted, proceed when the
matched benign twin is safe. OWASP and MCP security guidance provide the
standards context, but OPERANT remains an open self-reported benchmark until a
third-party rerun process exists.
